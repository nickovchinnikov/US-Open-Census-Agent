# Why WrenAI

This project uses [WrenAI](https://github.com/Canner/WrenAI) because the Census source is technically queryable but not naturally understandable. Its field names are compact Census codes (for example, `B01001e10`), while users ask for concepts such as “males aged 22 to 24.” WrenAI provides the semantic layer between those two forms.

Wren models give the agent stable, readable model names and column descriptions that preserve the Census metadata hierarchy, universe, and estimate-versus-margin-of-error distinction. This grounds generated SQL in reviewed definitions instead of exposing raw Snowflake tables and opaque column codes directly. The model files, business rules, and confirmed question-to-SQL examples are versioned in the repository, making the query context reviewable and reproducible.

## Current project state

- Snowflake is configured as the data source; credentials remain local in `.env`.
- The checked-in Wren semantic layer is valid: **9 models**, **0 views**, and **0 relationships**.
- Models cover the 2019 Census age/sex, commuting, county-FIPS, education, employment, geography, housing, income, and poverty data.
- Census column descriptions include semantic paths from the source metadata. For example, `B01001e10` is documented as the estimate for males aged 22–24 in the total-population universe.
- Three verified natural-language-to-SQL examples are stored as reusable Wren knowledge, including county population, Indiana household income, and county unemployment-rate questions.

The semantic foundation is ready for model-based analytical queries
